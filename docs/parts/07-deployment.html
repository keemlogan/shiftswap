7. Deployment and User Guide

This chapter explains how ShiftSwap is deployed and how it is used. Section 7.1 describes the deployment on GitHub Pages, what happens when the application is opened for the first time, how to reset or run it locally, and which browsers have been checked. Section 7.2 is a user guide organised by role and task, which follows the demonstration data of spec §10 through one complete substitution and then through attendance, weekly summary and payroll.

7.1 Deployment

7.1.1 Hosting on GitHub Pages

ShiftSwap is a static web application (NFR-08), so deploying it means publishing files; there is no server program to install or start. The repository is hosted on GitHub and published with GitHub Pages [13] from the root of the main branch, with HTTPS enforced. An empty .nojekyll file in the root tells GitHub Pages to serve the files as they are, without processing them. The table below gives the addresses.

Publishing a new version consists of committing the changed files and pushing them to main; GitHub Pages rebuilds the site within a few minutes. Because all URLs inside the application are relative, the files work unchanged under the sub-path /shiftswap/app/. The deployment was checked on 2026-09-27: the application URL returned HTTP 200 with the application's index.html, and the Pages configuration reported the status "built".

7.1.2 What happens when the application is opened

  1. The browser loads app/index.html, the style sheet, vendor/sql-wasm.js and the module main.js. While the database is being prepared, the page shows a loading message.
  2. main.js initialises sql.js, which loads the WebAssembly file vendor/sql-wasm.wasm (about 650 KB) from the same site. No database server is contacted.
  3. If the browser's localStorage holds a saved database under shiftswap.db.v2 with the current schema, it is opened. Otherwise the schema of spec §8 is created, the demonstration data of spec §10 is inserted — including each worker's work history since the contract start and the confirmed payroll up to August 2026 — and the database is saved. A database saved by a version before iteration 7, under shiftswap.db.v1, is not used. The demo clock is read from shiftswap.clock.v1 (default Monday 2026-09-28 09:00) and the language from shiftswap.lang; without a saved choice the interface is in Korean. The progress of the demo tour is kept under shiftswap.tour.v1, and an unfinished substitute request is kept in sessionStorage, so that a reload does not lose the flow.
  4. The router runs the System Clock — expireOverdue(), then prepareMonthlyPayroll() — and renders the sign-in screen, which doubles as a guided demo tour (Section 4.9). From now on, every change is saved to localStorage after its transaction commits.

The fonts (Pretendard and JetBrains Mono) are loaded from public font services. If they cannot be reached, the browser uses its own fonts; the application works the same, only its appearance differs. The first load therefore needs a network connection for the application files, and later work happens entirely in the browser.

7.1.3 Resetting and running locally

Reset. The Demo tools panel, opened from the demo-clock chip in the header, contains Reset demo data. After a confirmation in the panel, it deletes the saved database, recreates the demonstration data, sets the demo clock back to 2026-09-28 09:00 and returns to the sign-in screen. This restores the exact starting state of the scenarios in Section 3.8 and of the user guide. Clearing the site data in the browser has the same effect.

Local run. To run the application from a copy of the repository, serve the folder with any static web server and open the app/ path, for example:

git clone https://github.com/keemlogan/shiftswap.git
cd shiftswap
python3 -m http.server 8000        # then open http://localhost:8000/app/
npm install && npm test           # optional: run the automated tests (Chapter 6)

Opening app/index.html directly from the file system does not work, because browsers do not load WebAssembly and ES modules from file:// addresses; the application then shows an error message that asks the user to serve the folder over HTTP and reload the page.

7.1.4 Browser support

The application uses only standard features: ES modules, localStorage, sessionStorage and WebAssembly. It was tested in Google Chrome on desktop and in headless Chrome at 1280 px and 360 px width with tools/check.mjs (Section 6.7). NFR-06 also names Edge, Safari and Firefox; checks in these browsers had not been recorded when this chapter was written (Section 6.7). If a browser blocks storage, for example in some private-browsing modes, the application still runs, but data is kept only until the tab is closed.

7.2 User Guide

The guide follows the demonstration data through one complete substitution and then through the owner's other tasks. Dalbit Café has one owner, Park Jiyoung, and four part-time workers: Lee Seoyeon, Choi Minho, Jung Hana and Kang Doyun. The demo clock starts on Monday 2026-09-28 at 09:00, and Lee Seoyeon has already asked for a substitute for her Wednesday evening shift because of a midterm exam. The interface opens in Korean. Most screenshots are in English, which is selected in the header menu, and three show the Korean default. Desktop screenshots were taken at 1280 px width and phone screenshots at 390 px.

7.2.1 Signing in with the demo tour (all users)

The first screen is a guide to the demo. The 3-minute tour card lists three numbered steps; each step's button signs in as the right person and opens the screen where the step happens, and completed steps are marked. Below it, All accounts lists every person with a one-line summary, for example "Tue, Thu 18:00–23:00, Sat 12:00–18:00 · 16 h a week" for Choi Minho. There are no passwords. Once signed in, the header shows the store name, the demo-clock chip, the bell with the number of unread notifications, the current person (select it to View as someone else) and the menu with the language switch and Sign out.

7.2.2 Worker Home: answering a request (candidate)

A worker's Home lists what needs the worker now. For a candidate, the first card is the request: who asks, which shift, why, by when, and — before any button — what accepting would do to the candidate's own week. Accept takes one tap (NFR-01). A message then confirms that the shift is taken and that the owner will decide. If another candidate was faster, the card says so and closes. Can't is also one tap: it closes the card with a short confirmation and tells no one, unless it was the last answer missing and everyone has said they can't, in which case the request ends (Section 7.2.5). Further down, Home shows the next shift with Find a substitute, the week's scheduled and contract hours with the holiday allowance in words and money, and any past shifts still to record.

7.2.3 Requesting a substitute and following it (requester)

Find a substitute — on Home, on the Swaps tab or in the detail of one's own shift — starts a flow of three steps with a step indicator, a back arrow and a close button. Step 1 asks which shift; a shift that already has an open request is shown as "Already looking for cover" and cannot be chosen (BR-03). Step 2 asks for a reason (chips such as Exam or Family event, or free text) and a reply deadline (In 24 hours, 2 hours before or a chosen time), and repeats the deadline as a sentence; the default is the earlier of 24 hours from now and the shift start. Step 3 shows the request and the people who will receive it: every co-worker who is not already working at that time, computed at that moment (BR-01). If no co-worker is free, the step says so and explains that the owner will be told at once (FR-08).

The Swaps tab lists requests received, the worker's own requests and past requests. Each open request is a tracker with three steps — Requested, Accepted, Approved — with each co-worker's answer so far (waiting, can't or accepted) and a sentence saying what happens next; rejected, expired, cancelled and failed requests end with a labelled state and the reason. Cancel request withdraws an open request, and everyone it was sent to is told. The Me tab holds the worker's own profile — contract, weekly contract hours, hourly wage and phone, which only the worker and the owner can see (NFR-11) — and the attendance list, in which a past shift is recorded with Record. Since iteration 6 it has no availability editor: workers are no longer asked to maintain the times they could take extra shifts.

7.2.4 Owner Home: approving a swap (owner)

The owner's Home starts with the number of things to handle today and a decision card for each accepted swap. The card states the swap in one sentence and gives one line per person with scheduled hours before and after and the holiday allowance; if a worker's eligibility would change, the line is highlighted in amber. Details opens the full before/after comparison. Approve reassigns the shift, recomputes both workers' weekly summaries and informs both; Reject leaves the shift with the requester. Home also lists requests still waiting for replies, attendance records to confirm (Confirm or Mark absent), unacknowledged pay warnings, who works today, and the week's totals.

7.2.5 When nobody can take the shift (requester and owner)

Demonstration walkthrough S8 of the specification shows what happens when nobody can take a shift (BR-13, FR-22). Jung Hana requests a substitute for her Sunday shift, 4 October, 10:00–16:00. The request goes to Lee Seoyeon, Choi Minho and Kang Doyun; Doyun is asked because his own Sunday shift begins at 16:00, when Hana's ends. Each of the three signs in and taps Can't on the request card. The first two answers change nothing for anyone else, and Hana's tracker shows them as they arrive. With the third answer the request ends at once, without waiting for its deadline. Hana's Swaps tab then shows the card "Every co-worker said they can't cover this shift. Please contact the owner." The owner's Home shows a card "No one can cover" for Hana's Sunday shift, whose only action is Got it: there is nothing left for the system to try, and the owner settles the shift with Hana directly. Acknowledging removes the card. The same ending occurs immediately when a request is sent while no co-worker is free at that time.

7.2.6 The schedule (all users)

On wide screens the schedule shows the week as a time grid: seven day columns, an hour axis from 10:00 to 23:00, today marked, and each shift a block placed by its time. A shift with an open request has a dashed amber outline and the chip "Looking for cover"; a handed-over shift has an amber edge and stripes. A worker's own shifts are highlighted in blue, and the worker's primary action is Find a substitute. Selecting a shift opens its detail with its swap history and only the actions the viewer may take. For the owner these are Change time, Change worker and Delete; deleting is refused with its reason for a shift that has a request or an attendance record (FR-05). The owner's primary action is Add shift, or Create this week's schedule for a week without shifts (FR-04).

7.2.7 Pay: weekly summary and monthly payroll (owner)

The Pay tab has two segments. Weekly shows, for the chosen week, each worker's contract, scheduled and worked hours, whether the week earns the weekly holiday allowance, and the amount or the reason. For a week in progress the result is a projection, because scheduled shifts do not break attendance until they are marked absent.

Monthly shows the payroll of a month. The arrows ‹ › move between months, back to the first contract month, March 2026, and a chip next to the month shows its state: "Confirmed" (확정됨) or "Draft" (초안). Without a draft, the primary action is Create September pay draft, with the month named in the button. Each row has hours, base pay, holiday pay, premium and total, with flags: "Estimated" when some shifts have no confirmed attendance and are counted with their scheduled hours (BR-11), "Probation minimum 90 %" when all probation conditions hold (BR-10), and "Below minimum wage" with an explanation (BR-09). Confirm September pay stays disabled, with the reason written under it, until every warning has been acknowledged with Acknowledge; the acknowledgement is saved. A confirmed month is read-only. Rebuild draft replaces only draft rows, and warnings must then be acknowledged again. The note under the table explains that premium pay applies only with five or more regular employees.

The months before September come from the seeded work history and are confirmed, so they are read-only: the button at the top says that the month is confirmed, and the rows cannot be changed. Jung Hana has no row in August, because her contract starts on 1 September.

7.2.8 Last month's payroll prepared automatically (owner)

On or after the first day of a month, the System Clock prepares the previous month's payroll draft by itself (walkthrough S9 of the specification). To see it, open Demo tools and set the clock to 1 October 2026. The owner's Home then shows the card that the September payroll draft is ready; Review payroll opens Pay → Monthly for September and marks the notification as read. The draft is the same as one created by hand, and it carries the note "This draft was made automatically on the 1st of the month." (매월 1일에 자동으로 만든 초안이에요). The system never confirms a payroll: Doyun's below-minimum warning must still be acknowledged, and the owner confirms the month as described in Section 7.2.7. Moving the clock further within October creates no second draft and no second notification. If the owner has already created or confirmed the September payroll before 1 October, nothing is prepared.

7.2.9 Staff and settings (owner)

Staff lists the workers with contract hours, wage and contract period; Add worker is the primary action. A worker's detail holds the personal and contract data and the fixed weekly shifts, edited by choosing weekdays and times. The editor shows the resulting weekly contract hours, which decide the holiday allowance. Leave the contract end empty for an open-ended contract; the probation end is optional and is used only for the 90 % minimum-wage rule; Simple labour marks work that the law excludes from that reduction. Overlapping fixed shifts are refused with a message naming the conflict.

Settings holds the values that the pay rules depend on: the number of regular employees, which switches premium pay on from five; the treatment of shifts handed over by an approved swap; and the minimum wage by year. When a new minimum wage is announced, add a row for the new year; the program does not need to change.

7.2.10 Demo tools

The demo-clock chip in the header ("Mon 9/28 09:00") opens Demo tools, a pop-over on desktops and a sheet on phones. It contains the current demo time with Set this time, +1 hour and +1 day, and Reset demo data, which asks for confirmation inside the panel. Moving the clock past a request's deadline or its shift start makes the request expire the next time any screen is shown (UC-11), and the requester and the owner are told.
